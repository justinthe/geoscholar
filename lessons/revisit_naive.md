## Verdict

- Improved: model setup works, the corpus is real full text with section labels, and the "Sentinel-1" query now returns chunks that actually mention Sentinel-1. Out-of-domain and impossible questions now get the exact refusal instead of an invented answer or a wrong claim about the future.
- Still missing: no score threshold, so rice/Rendang still retrieve 5 irrelevant chunks (0.52-0.58) and `ask()` still prints them as Sources. The refusal relies on the model's obedience.
- Coverage is thin: for broad questions the top 5 chunks come from only 3 papers (and 2 papers for "Sentinel-1" took 4 slots). Intro chunks outrank Method chunks.
- Generation is the main remaining weakness: the bare query produced made-up questions, and the broad question mixes literature-review mentions with the papers' own methods, with no per-claim citation.
- Next fixes: (1) add a score cutoff (try about 0.65, re-tune on more queries) and skip the LLM and the Sources print when nothing passes; (2) retrieve more (k 10-15), cap chunks per paper, and prefer or filter on Method sections (or add a reranker plus hybrid BM25); (3) change the prompt to "one bullet per paper: method in one sentence, with [id, section]; ignore methods only mentioned as related work" and wrap bare keywords into a question; (4) add authors and a year range to the index/README so the 2025 question can be answered with "corpus only has 2026 papers".

Could not verify: whether the claims in the "Sentinel-1" answer match their cited chunks (the output was questions, not claims); the chunk text of every Sentinel-1 hit beyond a keyword match; the notebook's printed Sources output (inferred from code); and a threshold value, since only a few queries were sampled.
